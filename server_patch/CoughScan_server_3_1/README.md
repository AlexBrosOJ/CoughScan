# Сервер CoughScan 3.1 — замена main.py

Полный main.py подготовлен на основе AlexBrosOJ/Yam/main.py, полученного 17 ноября 2026. Это НЕ фрагмент для вставки: заменяется весь файл. На сервер ничего автоматически не загружалось; приложение iOS не менялось.

## Насколько мешали проверки

В 65 предоставленных записях однозначно размечены 58: 34 кашлевых, 24 без кашля; 7 неопределённых исключены. Текущая обработка на этих данных: 0/34 найденных кашлевых фрагментов. Модель без фильтра RMS и без штрафов, порог >0.50: 23/34 и 2 ложных на 24 отрицательных. Из живого кашля: 7/8 и 1 ложный на 20 отрицательных; из видео: 16/26 и 1 ложный на 4 отрицательных.

Это сравнение по тем же диагностическим оценкам, а не независимая проверка новой модели, и не количество отдельных кашлей. Порог 0.50 — стартовая тестовая настройка. На новых записях точность может отличаться. Базовая YAMNet и собственный классификатор — разные выходы; используем существующий собственный классификатор с прежним scaler.

## Что сохранено

- Все 14 прежних GET/POST/DELETE маршрутов, multipart-поля audio и device_id.
- Успешный JSON с status, probability, cough_detected, message, cough_count, confidence, record_id и download_url.
- Прежние модель cough_detection_final_optimized.keras и scaler cough_scaler_final_optimized.pkl. Их НЕ заменять другими версиями.
- Mono 16 kHz, первая секунда, peak-normalization, прежние MFCC и YAMNet mean/max embeddings: те же 2079 признаков.
- SQLite, таблица и существующие столбцы. Переименовывать/обнулять БД не нужно.
- Сохранение как положительных, так и отрицательных успешных анализов и выгрузка WAV/ZIP.

## Что исправлено

- По умолчанию выключены эвристические множители fast_enhanced_check и абсолютные отсечения RMS/peak; точный цифровой ноль по-прежнему считается тишиной без inference. Рабочий порог >0.50.
- Ошибки декодирования → HTTP 422; недоступная модель → 503; ошибка вычислений/диска → 500. Больше нет фиктивного «успех, кашля нет» при исключении. iPhone оставит такой WAV в очереди для повтора.
- Логируются исходная оценка, итог, порог, RMS, peak, clipping_fraction. При выключенных множителях probability == original_probability.
- Декодирование, признаки и inference не выполняются в asyncio event loop. Веса защищены блокировкой; обработка загрузок последовательная. Саму скорость модели этим не гарантируем: нужно измерить на сервере.
- Повтор запроса с теми же device_id, filename и SHA256 возвращает прежний record_id и не добавляет второй счётчик. Проверено внутри одного процесса; запускать с одним worker.
- Пустой файл → 400; размер более 5 MiB → 413. Временный WAV удаляется даже при ошибке.
- Срок хранения строк по умолчанию 120 часов вместо 1 часа, чтобы диагностические записи не терялись сразу. Лимит WAV остаётся 500: это максимум, а не обещание хранить 5 суток. При непрерывной записи 500 секунд — около 8 минут на все телефоны суммарно.
- Очистка видит и старые WAV без строк БД, удаляет только принадлежащие хранилищу cough_*.wav и очищает ссылки на удалённые файлы. Перед первым запуском обязательно сохранить копию старого хранилища, если записи нужны: лимит применяется реально.

## Как заменить

1. Скачайте main.py из этой папки.
2. На сервере определите рабочую папку текущего процесса и остановите сервер прежним способом (панель хостинга / systemd / Docker). Не запускайте второй процесс рядом на том же порту.
3. **В остановленном состоянии** скопируйте текущий main.py, cough_db.db и всю папку cough_audio_storage в резервную папку. Если SQLite имеет файлы -wal/-shm, сохраните их тоже. Сохраните прежние переменные окружения и команду запуска. Не храните резервные копии в публичном GitHub.
4. Замените только основной main.py новым. Оставьте прежние .keras, .pkl, БД, рабочую папку и зависимости. Не обновляйте весь requirements.txt ради этого патча.
5. Если на хостинге заданы настройки, выставьте:

```text
COUGH_THRESHOLD=0.50
ENABLE_LEGACY_ENHANCEMENT=false
MIN_RMS=0
MIN_PEAK=0
RECORD_RETENTION_HOURS=120
MAX_AUDIO_FILES=500
AUDIO_RETENTION_DAYS=5
```

Новые пути опциональны: DB_PATH и AUDIO_STORAGE_PATH. Если не заданы, используются прежние относительные пути. При рестарте сохраните прежнюю рабочую директорию, иначе откроется другая пустая БД и не найдутся модели.

6. Перезапустите прежней командой. Если запускаете вручную из папки проекта, в прежнем Python-окружении:

```sh
python -m py_compile main.py
python main.py
```

Либо, если раньше использовали uvicorn:

```sh
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1
```

Используйте один способ запуска, не оба. Порт/домен/TLS-прокси оставьте прежними. Новая сборка iPhone для этих серверных изменений не требуется.

## Проверка после замены

1. Откройте https://alexbrosoj-yam-134b.twc1.net/health . Ожидается:

```json
{"status":"healthy","server_version":"3.1","model_loaded":true,"scaler_loaded":true,"threshold":0.5,"legacy_enhancement_enabled":false,"min_rms":0.0,"min_peak":0.0}
```

В реальном ответе есть и другие прежние поля. Если версия/настройки не совпадают — запрос попал в старый процесс либо переменные окружения переопределяют значения. Если модель не загружается, смотреть traceback при startup и имена файлов, не менять scaler на случайный.

2. Повторите короткий тест на iPhone: живой кашель и фон отдельно, 30–60 секунд. Не форсируйте кашель ради теста. Проверьте, что очередь отправок уменьшается, а количество записей обновляется.
3. В логе ищите `analysis file=... orig=... final=... threshold=0.500 skipped=False cough=True/False`. Для обычного ненулевого звука orig и final должны совпадать. Модель может предсказывать ниже порога — это не ошибка загрузки.
4. Скачайте архив /coughs/audio/all и метаданные /records/all?limit=500&include_audio=true сразу после теста. В cough_stats теперь сохранены исходная оценка и диагностические поля.
5. Для ручного HTTP-теста используйте свой известный WAV, предварительно подставив настоящий путь:

```sh
curl -sS -i --max-time 60 \
  -F 'device_id=patch_manual_test' \
  -F 'audio=@/ПОЛНЫЙ/ПУТЬ/known_cough.wav' \
  'https://alexbrosoj-yam-134b.twc1.net/upload'
```

Ожидается HTTP 200, status=success, probability == original_probability, threshold=0.5, enhancement_applied=false. `cough_detected` определяется фактической оценкой — любой файл с названием cough не обязан распознаваться. Повтор того же запроса возвращает duplicate=true и тот же record_id. Плохой WAV должен вернуть HTTP 422, не NO_COUGH.

## Повторная проверка настоящих весов в Colab до развёртывания

В уже открытом диагностическом Colab с загруженными моделью, scaler и WAV вставьте весь colab_recheck.py в новую ячейку. Когда попросит файл, загрузите новый main.py. Ячейка извлечёт и выполнит ТОЛЬКО функции inference из этого файла — без FastAPI, базы, сервера и startup. Получите patch_recheck.csv и, если labels остались в памяти, фактическое сравнение с вашей разметкой. Если артефакты/версии и исходные WAV те же, ожидаемый ориентир — 23/34 и 2/24 на этой выборке; это не гарантия нового независимого теста.

## Что проверено локально

Все 16 автоматических проверок прошли (`Ran 16 tests — OK`). Синтаксис полного сервера и Colab-ячейки также проверен.

Интеграционные тесты test_server.py используют настоящие FastAPI HTTP-маршруты, multipart, librosa-декодирование/ресемплирование WAV, признаки MFCC/спектра, файловое хранилище и SQLite. Только TensorFlow/YAMNet embeddings/веса подменены детерминированными заглушками: настоящий TensorFlow и файл .keras здесь не запускались.

Проверены: тихий WAV не отбрасывается; оценка модели проходит без штрафов; положительные/отрицательные результаты сохраняются; цифровая тишина; пустой/повреждённый/слишком большой файл; недоступная/сломанная модель; повторные запросы; WAV/ZIP; статистика и старые маршруты; включение legacy-настроек; лимит сирот; удаление по сроку; совпадение вектора признаков с исходным кодом; граница порога; отказ диска и одновременные повторы.

Для повторения в отдельном тестовом окружении нужны numpy, librosa, fastapi, python-multipart, httpx, joblib, pytz, uvicorn, aiofiles:

```sh
python -m unittest -v test_server.py
```

Не запускать test_server.py в одном Python-процессе с рабочим сервером: тесты подменяют ML-модули и используют отдельную временную БД.

## Откат

Остановить новый процесс, вернуть резервный main.py и прежние переменные окружения, запустить прежней командой из прежней папки. Новая схема SQLite не вводится, поэтому БД совместима со старым кодом. Старый код снова будет применять проблемные фильтры. Для полного возврата состояния БД/аудио — восстановить их согласованную резервную копию в остановленном состоянии.

## Оставшиеся ограничения

- Первые секунды и фрагменты без перекрытия сохранены для совместимости модели; точный счёт событий кашля и защита от разрезания события требуют отдельного этапа.
- Неизвестны качество на других людях и ложные срабатывания за час непрерывного фона. Порог 0.50 ещё нужно проверить на независимых данных.
- Маршруты административной выгрузки/очистки по-прежнему не имеют собственной авторизации, как в исходном сервере. Защиту доступов и TLS нужно настраивать отдельно; в клиентский upload токен этим патчем не добавлялся.
